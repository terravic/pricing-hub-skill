# Pricing Hub Skill

The **Pricing Hub Skill** provides an end-to-end autonomous capability for ingesting provider contracts, fee schedules, and clinical reimbursement policies, calculating claim-line allowable amounts, detecting pricing discrepancies against ground truth, and tracking pricing loads in real time to prevent migration delays.

---

## 1. Scope & Capabilities

### Supported Lines of Business & Claim Types
- **Lines of Business**: `COMMERCIAL` (HMO/PPO), `MEDICARE` (Advantage & FFS), `MEDICAID` (Managed Care).
- **Claim Formats**: `PROFESSIONAL` (837P / CMS-1500) and `FACILITY` (837I / UB-04 Inpatient & Outpatient).
- **Claim Ingestion Interoperability**: Compatible with direct JSON and output schemas generated by the `x12-to-json-parser` skill.

### Excluded Scope (Enforced via Gate)
- **Dental Claims** (837D / CDT codes).
- **Vision Claims** (Routine retail/optometric hardware).
- **Pharmacy Claims** (NCPDP / outpatient script transactions).
> [!NOTE]
> Any excluded transaction is intercepted at the ingestion gate and routed with the reason code `REJECT_UNSUPPORTED_LOB_EXCLUSION`.

### Step 1: Contract and Policy Ingestion
Ingest contracts, rate cards, and clinical reimbursement policies from the repository:
```bash
python3 scripts/run_ingestion.py --contracts-dir data/contracts --policies-dir data/policies
```
- **What this does**:
  - Ingests rate cards (Physician Fee Schedules, DRG base rates, % of Billed Charges, Per Diem rates).
  - Validates schema, date continuity, and rate sanity (flags negative rates or missing fee schedules).
  - Ingests CMS LCD/NCD policies and commercial payer guidelines, indexing them by target procedure code and paragraph citation.

### Step 2: Automated Allowable Amount Verification
Execute parity verification on trial batches or the curated 100-claim Golden Dataset:
```bash
python3 scripts/run_verification.py --claims-file data/golden_dataset/golden_claims_all.json
```
- **What this does**:
  - Evaluates each claim through the [PricingRouter](src/pricing_engine/pricing_router.py).
  - Applies Multiple Procedure Payment Reduction (MPPR) 50% discount on secondary surgical procedures.
  - Applies Modifier -25 validation, diagnostic split modifiers (-26 / -TC), bundling edits (CPT 99000 -> CO-97), timely filing limits (CO-29), and inpatient DRG outlier payments.
  - Compares calculated allowable amounts against expected ground truth using [DiscrepancyDetector](src/verification/discrepancy_detector.py).
  - Emits an auditable Chain-of-Thought log citing exact contract clauses and policy paragraphs.

### Step 3: Real-Time Pricing Load Monitoring & Bottleneck Tracking
Launch the monitoring dashboard to observe pipeline migration health:
```bash
python3 scripts/monitor_loads.py
```
- **Categorical States**:
  - **`LOADED`**: Ingestion, validation, and baseline parity tests completed; ready for claim adjudication.
  - **`OUTSTANDING`**: Queued or in progress; calculating claim lines.
  - **`STALLED`**: Blocked by a detected bottleneck.
- **Bottleneck Diagnostics**:
  - `MISSING_FEE_SCHEDULE`: Rate card missing required CPT codes.
  - `PROVIDER_NPI_UNMAPPED`: Provider NPI missing from credentialing registry.
  - `RATE_CARD_DATE_OVERLAP`: Effective date window conflicts with an existing schedule.
  - `VALIDATION_VARIANCE_BREACH`: Batch allowable failure rate exceeds the 2.0% quality gate.
  - `DEPENDENCY_TIMEOUT`: Processing duration exceeded the 2-hour queue limit.
- **Alert Dispatch**: Emits real-time `CRITICAL` or `WARNING` alerts with actionable remediation steps.

### Step 4: Automatic Dashboard Generation & Interactive Inspector
Upon completing ANY requested task (such as contract ingestion, single .x12 claim adjudication, golden dataset verification, or pipeline monitoring), the skill automatically creates and updates the unified interactive dashboard at `src/ui/dashboard.html`.

- **Agent Operating Directive**:
  - Always verify that `src/ui/dashboard.html` is generated/updated upon task completion.
  - In your final response to the user, always provide a clickable relative link to [dashboard.html](src/ui/dashboard.html) along with instructions to inspect the results visually or run `python3 scripts/launch_ui.py`.
- **Interactive Capabilities in `src/ui/dashboard.html`**:
  - **Light & Dark Mode**: Persistent toggle switch using CSS custom variables.
  - **1. Ingestion Inspector**: View extracted rate cards, DRG weights, and CMS LCD/NCD citations.
  - **2. Interactive Adjudicator**: Real-time claim calculator for CPTs, modifiers (-25, -26, -TC, -51), and timely filing rules.
  - **3. Verification Parity**: Interactive filterable explorer for the 100 Golden Claims with expandable Chain-of-Thought logs.
  - **4. Load Pipeline & Bottlenecks**: State machine view with interactive "Resolve & Re-Ingest" remediation simulator.
  - **5. Multi-Cog Flow**: Interactive inspection of inter-cog payloads across Member, Benefit, Contract, and Pricing cogs.
  - **6. X12 EDI & JSON Transformer**: Live side-by-side inspection of raw ANSI ASC X12 EDI streams (.x12 / .edi) and normalized JSON schema models with live scope gate evaluation and allowable calculations.

## 3. Inter-Cog Pipeline Architecture

The skill simulates and verifies multi-cog handshakes across the enterprise claim lifecycle:

```
[ Member Pick Cog ] ──► [ Benefit Cog ] ──► [ Contract Pick Cog ] ──► [ Pricing Engine Cog ] ──► [ Verification Cog ]
   (Eligibility & LOB)     (Deductibles & SBC)  (Rate Card Match)       (Allowable & Modifiers)     (Parity & CoT Citations)
```

To run inter-cog integration tests:
```bash
pytest tests/test_cog_integration.py -v
```

## 4. Verification Suite

Run the complete 23-test validation suite covering unit, integration, and golden parity tests:
```bash
pytest -v
```

All 20 tests verify:
1. Ingestion of contracts and policies without loss or corruption.
2. Immediate rejection of Dental, Vision, and Pharmacy claims.
3. Accurate fee schedule, DRG case rate, and % of charges allowable calculations.
4. Multiple procedure payment reductions (MPPR) and diagnostic modifier splits (-26, -TC).
5. Bundling edits (`CO-97`), timely filing denials (`CO-29`), and high-dollar suspensions (> $100k).
6. 100% concordance on the 100-Claim Golden Dataset.
7. Real-time load state transitions and stalled bottleneck pinpointing.
